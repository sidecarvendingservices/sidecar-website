# v1.10.2 — Deploy + What's Left For You

Everything below is the wrap-up for tonight's batch. Sections 1–2 are what
you need to run before/after deploying. Section 3 is the full "what shipped"
list. Section 4 is what did **not** ship — either deferred on purpose or
scoped down — so nothing gets lost.

## 1. Run the new D1 migration

One new migration this batch, `016_contracts_demo_resources.sql` (creates
`property_contracts`, `contract_machines`, `property_contract_ack`,
`demo_resources` — Property Contracts and the Demo Resources shelf both
degrade gracefully with empty lists until this runs, nothing else breaks):

```
npx wrangler logout
npx wrangler login
npx wrangler d1 execute sidecar-ops --remote --file=migrations/016_contracts_demo_resources.sql
```

No new R2 bucket needed — contracts and demo resources both reuse the
existing `RECEIPTS` bucket binding, just under a `contracts/` or
`demo-resources/` folder prefix.

## 2. Deploy


`dist/ops-dashboard.html` is already built and copied into your folder —

## 3. Everything that shipped this batch

- **Machines page** — full-width table, sortable, new **Next Service**
  column (reuses the Restock Queue's already-computed data, no new HAHA
  calls added).
- **Expenses** — Edit action (new PUT endpoint), same Edit added to
  Reimbursements. Missing-receipt flag ("No Receipt" tag + filter toggle).
  Attach-receipt-after-the-fact from inside Edit.
- **Case Calculator** — live cost/unit calc under Add Inventory's Package
  Price/Qty fields, prefills the line-item cost.
- **QMOS edit/delete** — Delete reverses the FIFO draw back to source lots
  and removes the linked expense; Edit is delete-then-recreate under the
  hood; rows now group by the shared `refId` for multi-lot entries.
- **Backstock shrink/inventory adjustment** — new "Adjust Inventory" button
  per row, "Inventory deficit · N unit(s)" wording under the product name
  when short.
- **Property contracts** — upload/view/delete a signed contract per
  property from Property Detail, with per-machine coverage checkboxes
  (defaults to all machines, unchecked ones stay uncovered — new machines
  never silently inherit an existing contract). "No Contract —
  Acknowledged" button for properties that genuinely don't have one on
  file. Missing-contract flag now shows up in both the Overview "What
  Needs Attention" widget and the Data Health checklist.
- **Backstock Sourcing Priority** — new card on the Backstock tab: on-hand,
  draw rate, runway, sorted soonest-critical first.
- **Demo/Site Consultation Resources** — new "Resources" nav tab (in the
  "More ▾" menu), upload/list/view/delete. Empty until you add real
  content — no code work left, just upload from the tab once deployed.
- **Google Ads** — Cost/Click and Cost/Conversion KPI tiles and campaign
  table columns.
- Plus the smaller bug fixes from earlier tonight: Data Syncs merged into
  Data Health, the `p.name`→`p.productName` bug that broke global search
  and a few Action Center labels, the "from HAHA" pill removed from
  Products, Metric Dictionary modal scroll position, Action Center/Overview
  font-size fix, and the missing nav divider line.

## 4. What didn't ship — deferred, not forgotten

- **§6 Planogram (view/edit)** and **§7 Per-machine pricing/margins** — not
  started. Both are HAHA-dependent; §6 has an open question (does HAHA's
  planogram response include per-lane capacity, or just product
  assignment?) that needs confirming before it's buildable. Natural next
  batch once tonight's changes are verified live.
- **§8 Remote device control** — not started, and per the spec itself this
  is deliberately the *last* feature built, since it needs permissions
  enforcement and audit logging proven solid first (both of which shipped
  in v1.10.1) plus real command-state/failure handling designed in.
- **§9 Batch-level expiration tracking** and **§10 QMOS expiration →
  auto-task** — not started this batch, cut for time. Existing single-date
  expiration tracking keeps working as-is in the meantime; nothing
  regresses.
- **§15 Role-scoped access enforcement** — intentionally a fast-follow per
  the spec, not tied to a fixed release. The enforcement *mechanism*
  shipped in v1.10.1 (F5); this is about actually assigning restricted
  roles to real non-admin users when that becomes needed.
- **§11 Property Contracts — Documents tab (Machine Workspace) view.** The
  spec called for this living in two places: Property Detail (shipped) and
  a per-machine Documents tab. Only Property Detail was built tonight —
  scoped down to keep the batch shippable. Worth a follow-up pass to add
  the per-machine view, probably alongside whichever future batch touches
  the Machine Workspace next.
- **§1 Machines redesign — Add Machine modal.** Spec called for Add
  Machine moving into a dedicated modal; the existing inline-edit-row flow
  was kept instead (already functional, just not a modal) to keep scope
  down. Cosmetic/consistency item, not a missing capability.
