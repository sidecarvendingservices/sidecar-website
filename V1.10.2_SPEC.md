# Command Center — v1.10.2 Spec: Feature Release

Second of two releases — **depends on v1.10.1 shipping first.** Every
feature below assumes the foundation from that release already exists:
the Machine Workspace (not a modal), the shared table/form/dialog
patterns, the permissions enforcement mechanism, and the Metric
Dictionary's definitions. Section numbers below are renumbered from the
original single v1.10 draft; original section references are noted
where useful.

---

## 1. Machines page redesign (was original §5)

**Current state:** two-column layout — Machines table (left) and
"Add a Machine" form (right), both always visible.

**Changes:**
- Machines table becomes full-width.
- "Add a Machine" moves into a modal (per v1.10.1 F12's form→modal
  pattern), opened via a **"+ Add Machine"** button in the card header.
- **Add Machine flow itself changes per v1.10.1 F14**: select Property
  first, inherit address/contacts/account manager/stocker, explicit
  override available rather than re-entering everything by hand.
- **Next Service Date column** added to the table directly, sortable,
  same urgency color treatment as elsewhere.
- Table itself uses v1.10.1 F12's standardized table behavior (sticky
  header/id column, sortable, row action menu) rather than a bespoke
  layout.

---

## 2. Expenses: edit, missing-receipt flag, Reimbursements edit, expense-type tooltip (was original §7, §8, §9)

**Current state:** `expenses.js` supports POST/DELETE only — no edit.
`receiptRef` field exists but nothing flags when it's empty. Reimbursements
reads the same `expenses` data but has no edit action of its own.
`expenseType` exists with no guidance on operating vs. capital.

**Changes:**
- New `onRequestPut` in `functions/api/data/expenses.js`.
- Edit action (via the row action menu from v1.10.1 F12) opens the same
  form as Add Expense, pre-filled, in a modal/drawer per F12.
- **Missing-receipt flag**: visible tag on any expense with an empty
  `receiptRef`, plus a filter toggle to isolate them. Uses the "distinct
  visual states" system from F12 (a genuine warning state, not reusing
  the same red as everything else).
- **Attach Receipt after the fact**: inside Edit Expense, if `receiptRef`
  is empty, an upload control appears right there (reusing the existing
  receipt-upload.js flow).
- **Same Edit action added to the Reimbursements table** — same modal,
  same underlying record, no new endpoint needed beyond the PUT above.
- **Operating vs. Capital/Equipment tooltip** on the Expense Type field:
  > **Operating** — day-to-day running costs: product purchases,
  > commissions, gas/mileage, small repairs, cleaning supplies.
  > **Capital/Equipment** — lasting value beyond this period: a new
  > machine, major component replacement, anything you'd still be
  > using or reselling a year from now. Rough threshold: >~$500 and
  > outlasting this quarter leans capital — confirm with your accountant.
  Worth a two-minute check with whoever does your books on the exact
  wording/threshold before finalizing copy.
- **Negative Backstock alert wording fix** from v1.10.1 F13 ("Inventory
  deficit · 1 unit" + Record Purchase/Adjust Inventory buttons) is a
  small piece of this same expense/inventory surface — implement
  together.

## 3. Case Calculator (was original §11)

**Changes:** unchanged from original scoping — embedded in Add
Inventory, total case price + unit count → cost/unit, prefills the
purchase batch line-item cost field. Pure UI helper, no backend change.
Uses F12's modal pattern for the calculator's own small form.

---

## 4. QMOS: edit / delete (was original §10)

**Changes:** unchanged from original scoping — Edit and Delete per QMOS
row; Delete reverses the FIFO draw back to source lots; Edit implemented
as reverse-then-recreate under the hood. Delete confirmation uses the
existing `confirmDialog()` pattern, now meeting v1.10.1 F4's full dialog
accessibility bar (naming, focus trap, focus restoration) rather than
the prior baseline.

---

## 5. Negative Backstock — shrink/inventory adjustment (was original §20)

**Changes:** unchanged from original scoping — new Shrink/Inventory
Adjustment action on Backstock, per-product, creates a positive
adjustment lot logged with its own `adjustment` move type, cost basis
defaulting to $0 and editable. Also usable in reverse for genuine
shrink/loss on positive stock. Directly wired to the "Adjust inventory"
button introduced by the negative-backstock alert rewrite in §2/F13.

---

## 6. Planogram — view & edit (was original §2)

**Current state:** not built. HAHA exposes Get Planogram, Set Market
Planogram, and Check Mutually Exclusive Products.

**Changes:**
- New proxy endpoints (`functions/api/haha-planogram.js`), same
  `hahaGet()` pattern as existing HAHA endpoints.
- Lives in the Machine Workspace's **Assortment & Pricing** tab (per
  v1.10.1 F2), not a standalone section — shown as a grid mirroring the
  physical machine where practical.
- Editing: **non-drag** product assignment per lane (per v1.10.1 F20's
  accessibility requirement — no drag-only interaction), "Check Mutually
  Exclusive Products" run before save, conflicts surfaced as a warning.
- **Gated by permissions** (v1.10.1 F5) — editing requires Admin (or
  whatever role gets assigned that permission later).
- **Every edit logged to Activity & Audit History** (v1.10.1 F17) —
  before/after layout, who changed it, when.
- Open question carried over: does HAHA's planogram response include
  per-lane capacity, or just product assignment? Confirm on build.

---

## 7. Per-machine pricing + Products page margin view (was original §3, §18)

**Current state:** Products table shows one flat price/margin per
product, pulled from HAHA's catalog — doesn't reflect that pricing is
confirmed to vary machine-to-machine.

**Changes:**
- Price shown and edited per-lane in the Assortment & Pricing tab
  (alongside planogram, §6) — never a fleet-wide change from this
  screen.
- Products page (redesigned in v1.10.1 F8) gets a **"Prices by
  Machine"** drill-down per product — the row drawer from F8 opens to a
  list of every machine stocking that product, with retail price,
  machine-side cost basis, and **net profit %**.
- **Net profit flagged if under 50%**, using F12's distinct-severity
  visual system.
- Products table's own Margin column becomes an aggregate/range summary,
  drilling into the per-machine dialog for detail.
- Same permissions gating and audit logging as §6.

---

## 8. Machine troubleshooting / remote control panel (was original §4)

**Current state:** not built. HAHA exposes Set Device Status, Reboot
Device, Set Temperature under Market Management; "freeze" and "open
door" need endpoint confirmation at build time (see original notes).

**Changes:**
- Lives in the Machine Workspace's **Health & Controls** tab.
- Four actions: View/Set Temperature, Freeze Unit, Open Door, Restart
  Device.
- **Confirmation dialog on all four**, meeting v1.10.1 F4's full dialog
  accessibility bar — clearly naming the machine and action.
- **Gated by permissions (F5) — Admin-only at launch**, per the audit's
  explicit P0 finding that remote device control must ship with real
  enforcement, not permission labels alone.
- **Every action (attempted and completed) logged to Activity & Audit
  History (F17)** — this is the audit's explicit precondition for
  shipping this panel at all: permissions, audit history, and
  command-state/failure handling need to be proven working *before* this
  ships, not simultaneously with it. **This is deliberately the last
  feature built in this release.**
- Successful actions also auto-log to the machine's Tasks & Calls
  history (Service & Activity tab), same as originally scoped.
- Command-state handling: each action needs a clear pending/success/
  failure state shown inline (not just fire-and-hope) — a restart or
  door command can fail or time out, and that needs to be visibly
  different from success.

## 9. Batch-level expiration tracking (was original §16)

**Current state:** `product_expiration` stores one overwritable date per
(machine, product); this already feeds `nextServiceBy` 3 days early —
that behavior already works, this is about the underlying data model.

**Changes:**
- Lives in the Machine Workspace's **Inventory & Restock** tab.
- `product_expiration` becomes batch-based: quantity + best-by date per
  entry, multiple batches per product/machine coexisting.
- Entry via a "Track Expiration" action: pick product, enter quantity,
  enter best-by date off the package.
- Soonest-expiration logic driving `nextServiceBy` pulls from the
  earliest best-by date with remaining quantity across batches, same
  3-day buffer as today.
- Display becomes a small sorted list when more than one batch exists,
  instead of one date.
- Quantity decrement mechanism (manual vs. sales-tied) still needs a
  quick decision at build time, per original notes — HAHA's sales data
  isn't necessarily batch-aware.

## 10. QMOS expiration pattern → auto-task (was original §17)

**Changes:** unchanged from original scoping — scheduled analysis of
`expired`-reason QMOS entries grouped by product+machine over a rolling
window; auto-creates a "consider reducing facings" task past a tunable
threshold. More accurate once §9 lands, but can ship against the
existing single-date data first if you'd rather not wait.

---

## 11. Property contracts (was original §12)

**Current state:** not built; no document storage on Properties today.

**Changes:**
- Lives in the Machine Workspace's **Documents** tab (per-machine
  view) and a corresponding section on Property Detail (property-wide
  view of every contract and what it covers).
- Upload signed contract (PDF/image) to R2, new `property_contracts`
  table with a machine-id join.
- **Machine tagging defaults to all machines at that property**, all
  pre-checked, uncheck to scope narrower.
- **New machines require explicit contract assignment** — no automatic
  inheritance from an existing "all machines" contract.
- **Missing-contract flag** on both Properties and the specific
  uncovered Machine(s), using F12's warning visual state.
- **"No Contract — Acknowledged"** resolution path clears the flag
  without requiring a document, tracked as its own deliberate state
  (not silent suppression). New machines start unflagged-until-checked
  on their own.
- Every upload/edit logged to Activity & Audit History (F17).

## 14. Google Ads — cost per click & cost per conversion (was original §6)

**Changes:** unchanged from original scoping — two KPI tiles and two

## 15. Role-scoped access enforcement (fast-follow, not fully in this release)

**Current state after v1.10.1:** Admin, Stocker, Receiver, Sales, and
Account Manager exist as assignable role values, and the enforcement
*mechanism* exists and is actively gating §6–§8 above for Admin-only
access. Only Admin is meaningfully defined in terms of what it can see
and do.

**Changes (once a real non-admin user exists):**
- Define what each of Stocker/Receiver/Sales/Account Manager can
  actually see and do — e.g., a Stocker likely only needs Restock
  Queue, Machine Workspace's Inventory & Restock tab, and QMOS, with
  financials hidden entirely.
- This is intentionally left open rather than guessed at now — easier
  to get right against a real second user's actual workflow than to
  design in the abstract.

## v1.10.2 build order

Assumes v1.10.1 has already shipped in full.

1. **§1 — Machines redesign.** Builds directly on v1.10.1's Machine
   creation fix (F14) and shared table pattern (F12) — natural first
   feature once the foundation is live, low risk.
2. **§2 — Expense editing, missing-receipt flag, Reimbursements edit,
   expense-type tooltip.** One backend change unlocking multiple
   surfaces.
3. **§3 — Case Calculator.** Small, self-contained.
4. **§4 — QMOS edit/delete.** Contained to one tab, needs care on the
   FIFO reversal logic.
5. **§5 — Negative Backstock shrink/adjustment.** Pairs naturally with
   §2's inventory-deficit alert rewrite.
6. **§6 — Planogram (read-only first, then editing).** Confirm HAHA's
   response shape before committing to final UI.
7. **§7 — Per-machine pricing + Products margin view.** Grouped with §6
   since they share the same Assortment & Pricing surface and price
   data.
8. **§8 — Troubleshooting/remote control panel.** Deliberately last —
   depends on v1.10.1's permissions enforcement and audit history having
   been live and proven for a while by this point, per the audit's
   explicit sequencing recommendation.
9. **§9 — Batch expiration tracking**, then **§10 — QMOS expiration
   pattern auto-task**, in that order since §10 gets more accurate with
   §9's data.
10. **§12 — Backstock sourcing priority/runway.** Self-contained, no
    dependencies on anything above.
11. **§11 — Property contracts.** Needs the Documents tab (part of
    v1.10.1 F2) already in place, otherwise self-contained.
12. **§14 — Google Ads CPC/CPA tiles.** Trivial, can ship anytime,
    included here rather than earlier just to keep this list roughly
    priority-ordered.
13. **§13 — Demo/Consultation Resources.** Lowest urgency — content
    comes from you later regardless of when the shelf ships.
14. **§15 — Role-scoped access enforcement.** Ongoing fast-follow rather
    than a fixed point in this sequence — starts whenever a real
    non-admin user needs defined access.

Let me know if you want to reorder, cut, or add anything in either
release before we start building v1.10.1.
